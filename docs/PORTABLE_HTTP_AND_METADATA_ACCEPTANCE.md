# Local authentication transport and first shared metadata operations

The local authentication HTTP library accepts only a factory-owned admission
from the exact Fetch Request and actual IncomingMessage/listener pair. Numeric
loopback development ingress is explicit; headers and a configured HTTPS URL
cannot establish TLS or proxy authority. Login has a4096-byte streaming limit,
canonical bounded credentials and deployment-owned source/clock inputs. The
bearer stays in an HttpOnly/SameSite cookie; JavaScript receives a domain-separated
CSRF derivation. Unsafe requests require exact Origin and constant-time CSRF
admission. Current sessions/accounts/credential revisions/grants are read again;
rotation and logout do not reuse an expired or revoked principal. Denials,
including a closed database, keep private,no-store and fixed errors.

The private keyring reader opens a preprovisioned private owned regular one-link
file through canonical nonwritable ancestors, checks inode/metadata before and
after asynchronous import, bounds4096 bytes and erases its byte buffer. It
reopens each operation for provisioned rotation. Exact filesystem-root ownership
can be pinned by trusted deployment configuration (defaultUID0); every other
ancestor retains serviceUID/rootUID0 rules. The cloud fixture explicitly used
rootUID65534. It never automatically trusts an observed root or generates keys.

Four existing Samples metadata operations now share a neutral SQL/service/HTTP
surface: create, update, soft deletion and restore. Worker registrations and
middleware remain in their previous positions. Genuine Node SQLite and genuine
D1 adapters retain atomic writes, direct affected-row counts, CAS/title audit,
exact safe numeric boundaries and existing pinned-cell truthiness. Non-idempotent
create failures still propagate; no uncertain acknowledgement is invented.
