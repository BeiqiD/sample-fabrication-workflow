## Project ownership change

The actual authenticated directory handler provides an opaque SHA256 witness.
Its closed purpose/version, explicit authentication family, deployment-owned
realm context and actual middleware actor distinguish creation owners. The JSON
directory body is unchanged. No actor email, cookie, session bearer, grant,
membership or File authority is delivered by this witness. The client owns that
response metadata in a WeakMap. A generic Node read surface issues a witness only
when its composer explicitly supplies `node-local` and its genuine installation
context; missing metadata leaves reads usable and creation unavailable.

The explicit creation request preserves its original JSON body and sends the
expected witness in an optional request header. The Worker compares it to its
own authenticated current request actor before parsing input or running service
SQL. A mismatch fails closed. Existing clients without that header retain their
existing behavior. All actual Project create/replay SQL and domain guards remain
unchanged. This is request ownership, not resource membership authorization.

The browser retains the exact original input before POST under its subject's
session-storage key. Cancel closes the form while keeping an unknown input.
Actual route unmount/document navigation can restore it after a matching current
directory read. Explicit Retry uses the same Project/title/operation ID. No read,
mount, refresh or sign-in automatically submits it. The submitted title stays
immutable while its result is unknown. A confirmed exact receipt clears only its
own matching input. Explicit known rejection can clear a new input; rejection of
a later Retry does not prove that an earlier unknown request never committed.

The real local authentication client's logout/identity delivery fences visible
state and late responses. Other owners do not restore an earlier owner's input;
the unknown original remains dormant for its own reconciliation. A late old ACK
cannot clear another owner's current ref, busy state or stored input. Directory
GETs, including Retry and Refresh, share abortable ownership. There is no second
directory GET before each submit: the actual POST witness comparison provides
the required current-actor fence without redundantly fetching the whole directory.
